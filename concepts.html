Seven concepts behind the exchange

These terms apply across HTTP versions, even when the wire format and transport change.

  1. Request and response

    The client sends a request describing a target and intended action. The server or an intermediary returns a response with a status and related information.

  2. Method

    The method states what the client wants done. GET retrieves a representation; POST submits content for processing. Safe and idempotent describe important method properties; they are not interchangeable.

  3. Status code

    The response status summarizes the outcome. Its first digit groups the class: 2xx success, 3xx redirection, 4xx client error, and 5xx server error.

  4. Header field

    Fields carry metadata, such as media type, caching instructions, content negotiation, or authentication information. The IANA HTTP Field Name Registry tracks registered names.

  5. Representation

    A representation is data describing a resource in a format such as HTML, JSON, or an image. Content-Type tells the recipient how to interpret its media type.

  6. Cache

    A cache can reuse a stored response when freshness and validation rules allow it. RFC 9111 defines HTTP caching, including Cache-Control and validators.

  7. Statelessness and application state

    HTTP’s core exchange does not require a server to remember prior requests. Applications add state with cookies, sessions, tokens, and storage. Cookie handling also has privacy and security consequences.

Try an observation in your browser

  1. Open a page and choose the browser’s Developer Tools.
  2. Select the Network panel and reload the page.
  3. Choose a request and inspect its method, status, fields, protocol, and timing.
