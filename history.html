02 · The timeline

HTTP grows with the web

As pages added more content and users, HTTP gained richer messages and more efficient ways to move them.

From research project to global platform

Tim Berners-Lee proposed the World Wide Web at CERN in 1989. Early web software paired addresses, hypertext, a browser, a server, and HTTP. CERN’s history describes the first web server and browser and the later release of the web software. Read CERN’s account.

  1. HTTP/0.9A small GET request and an HTML response suited the early, text-focused web.
  2. HTTP/1.0Version information, status codes, headers, and response metadata made messages more expressive.
  3. HTTP/1.1Persistent connections and clearer caching, routing, and message rules supported more complex sites.
  4. HTTP/2Binary framing and multiplexed streams improved how exchanges could share a TCP connection.
  5. HTTP/3QUIC changed the transport under HTTP while keeping its core semantics familiar.

Compare the major stages

These summaries use HTTP/1.0, HTTP/1.1, HTTP/2, and HTTP/3.

Why HTTP/1.1 was not the end

Persistent connections avoid reconnecting for every resource, but modern pages may request many resources. HTTP/2 introduced concurrent streams over one TCP connection. This helps many workloads, although TCP still delivers bytes in order: packet loss can delay data for multiple streams sharing that connection. HTTP/3 uses QUIC streams to avoid that particular cross-stream delivery dependency. Performance still depends on the network, server, browser, and workload; a newer version is not automatically faster in every situation.
